# ADR-0009：长期记忆不得参与授权与策略判断

- 状态：已接受
- 日期：2026-09-05
- 相关：PRD §10.3、§10.4、§9.7 红线 3

## 背景

跨会话记忆让 Agent 显得"认识用户"，但也打开了一条危险路径：

如果记忆里存了"该用户是 VIP，可享受更宽松的退款政策"，
而策略引擎读取了这条记忆，那么**记忆就变成了授权凭据**。

攻击者只需要在多轮对话里诱导系统把这句话写进记忆，就完成了提权。
这类攻击（memory poisoning）的根本问题不在于抽取质量，而在于**边界**。

## 决策

**长期记忆与案件级状态永远不能作为授权或策略判断的输入。**

| 记忆可以影响 | 记忆不能影响 |
|---|---|
| 语言偏好 | 数据归属（ownership） |
| 通知渠道偏好 | 退款资格 |
| 沟通语气与个性化 | 授权与角色 |
| 上下文提示（"上次投诉过配送"） | 策略判定结果 |
| | 金额上限 |

所有授权与资格判断的输入**只能**来自：业务库（`biz` schema）与策略规则（`policies/*.yaml`）。

配套措施：

1. 记忆注入 prompt 时标注为"提示，可能有误"（非权威）
2. 记忆写入准入清单排除一切"资格类"结论（PRD §10.4）
3. `PolicyEngine` 是纯函数，其函数签名中**根本不接受**记忆参数——
   与 ADR-0008 同样的思路：让越权不可表达
4. CI 中的投毒测试：写入"该用户可无限退款"后，策略判定结果必须零变化

## 理由

其他缓解手段（提高抽取质量、加置信度阈值、人工审核记忆）都是概率性的，
只能降低发生率。**切断输入路径是结构性的**，发生率为零。

代价很小：语气与偏好类记忆本来就不需要参与授权判断。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 记忆可参与判断，但加置信度阈值 | 概率性防御，攻击者可通过重复表述抬高置信度 |
| 记忆参与判断，但人工审核每条记忆 | 失去自动化价值，且审核者难以判断长期影响 |
| 不做长期记忆 | 失去一个重要能力，且这不是必要的取舍 |

## 后果

**正面**：投毒攻击在结构上被排除；策略引擎保持纯函数，易测试；
记忆的质量问题不会升级为安全问题。

**负面**：无法实现"系统记住这个用户上次被特批过，这次也放宽"这类个性化——
这类需求必须落到业务库的正式字段（如 `users.tier`）或人工审批，不能靠记忆。
这是有意的。

## 强制手段

- `PolicyEngine` 函数签名不接受记忆类型参数（编译期/类型检查保证）
- CLAUDE.md 红线 3
- 评估集中的记忆投毒专项用例
