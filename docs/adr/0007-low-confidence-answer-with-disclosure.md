# ADR-0007：低置信检索采用"带声明回答 + 转人工入口"

- 状态：已接受
- 日期：2026-09-05
- 相关：PRD §9.4 规则 10.5 / 14 / 14b、§11.1、§12.4

## 背景

检索分数落在中间地带时（有一些相关内容，但证据不够强），有两种处理方式：

- **保守**：一律转人工
- **积极**：带明确不确定性声明地回答，并提供转人工入口

保守方案安全但会让升级率虚高，且很多本可自助解决的问题被推给人工。

## 决策

**采用积极方案，但加三个约束把风险收口。**

阈值划分：

```
max_score < τ_low            → REQUIRE_HUMAN / RETRIEVAL_NO_RESULT
τ_low ≤ max_score < τ_high   → 低置信带
max_score ≥ τ_high           → 正常回答
```

低置信带的处理（升级矩阵规则 14）：
`ANSWER` + `confidence=low` + `reason_code=RETRIEVAL_LOW_CONFIDENCE`
+ 确定性声明模板 + `handoff_offer`。

**不新增 `DecisionOutcome` 枚举值**——用 `reason_code` 区分即可，
终态数保持 6 个，评估断言不受影响。

### 三个约束（缺一不可）

1. **只适用于纯信息类问答。**
   一旦本轮涉及退款资格、金额、权限或任何写操作，低置信一律转人工
   （规则 10.5，`LOW_CONFIDENCE_ON_DECISION`），不论用户问得多像"随便问问"。
   评估集中专门放 2 条"看似信息类、实则隐含资格判定"的陷阱题验证这条。

2. **声明文案是确定性模板**，由 `respond` 节点拼接，不交给 LLM 自行把握措辞。

3. **必须有引用。** 低置信不等于允许无据回答；一个可引用 chunk 都拿不出来时
   退回 `REQUIRE_HUMAN`（规则 14b）。

### 阈值标定方法

`τ_low` / `τ_high` **不允许拍脑袋**。Phase 2 的流程：

1. 用 golden dataset 的 RAG 用例跑检索，记录 `max_score` 与人工标注的"是否真有答案"
2. 画正负样本分数分布
3. `τ_low` 取负样本 95 分位，`τ_high` 取正样本 5 分位
4. 最终取值与分布图记录在本 ADR 的附录（Phase 2 补充）

## 后果

**正面**：升级率下降，自助解决率上升，用户体验更好。

**负面**：引入了新的错误面——低置信回答可能是错的。
用以下手段让它可测量、可回滚：

- 新指标 `low-confidence answer precision`，门槛 ≥ 90%，低于则上调 `τ_low`
- 反向断言：低置信回答不得出现"一定 / 必须 / 保证"等确定性措辞（关键词级检查）
- RAG 类评估用例从 6 条增加到 10 条，其中 4 条专门覆盖这个中间带

## 复审条件

若 `low-confidence answer precision` 连续两个版本低于 90%，
回退到保守方案（低置信一律转人工）。

## 附录：阈值实测值（Phase 2 标定，2026-09-05）

### 怎么跑出来的

```bash
cd ~/Desktop/ca-phase2
uv run python scripts/calibrate_tau.py --real              # 原句直接检索
uv run python scripts/calibrate_tau.py --real --rewrite    # 叠加 FR-302 查询改写
```

脚本读 `data/golden/rag.yaml` 的 10 条用例，按 `expect` 反推样本类型（不看 notes，避免主观）：
期望 `RETRIEVAL_NO_RESULT` 为负样本，期望 `RETRIEVAL_LOW_CONFIDENCE` 为低置信样本，
期望 `LOW_CONFIDENCE_ON_DECISION`（RAG-009/010，绑定了具体订单的资格陷阱）走的是矩阵规则 10.5
而非检索分带，**不参与分位计算**，其余为正样本。

向量：OpenAI `text-embedding-3-small`(1536)，`top_k=8`，分数 = 余弦相似度。

### 两次实测

| 用例 | 类型 | 原句检索 | 叠加查询改写 | 改写后的 query |
|---|---|---:|---:|---|
| RAG-001 | 正 | 0.5738 | 0.5773 | 退款政策 期限 天数 |
| RAG-002 | 正 | 0.7676 | 0.7114 | 金卡会员 权益 功能 |
| RAG-003 | 正 | 0.7407 | 0.7332 | 电子产品保修期 时长 |
| RAG-004 | 正 | 0.5221 | 0.5732 | 保修 不保 条件 范围 |
| RAG-005 | 正 | 0.7630 | 0.6757 | 投诉 处理 回复时间 期限 |
| RAG-006 | 负 | 0.4582 | **0.4126** | 海外直邮 关税 国际物流 海关 |
| RAG-007 | 低置信 | 0.5784 | 0.5468 | 退款 到账 时间 |
| RAG-008 | 低置信 | 0.5612 | 0.6570 | 会员 金卡 积分 使用 兑换 抵现 |
| RAG-009 | 陷阱 | 0.6651 | 0.6295 | 食品订单退款资格条件 订单 82916 |
| RAG-010 | 陷阱 | 0.5616 | 0.5805 | 订单82931 退货 运费 会员金卡 优惠 |

关键变化是**正负样本之间的间隔**：

| | 负样本最高 | 正样本最低 | 间隔 |
|---|---:|---:|---:|
| 原句检索 | 0.4582 | 0.5221 | 0.0639 |
| 叠加查询改写 | 0.4126 | 0.5732 | **0.1606** |

查询改写把间隔拉开到 2.5 倍。原因是口语句子里的寒暄与句式本身带语义，
会把"未覆盖主题"的分数抬起来；改写成主题词后，负样本掉得比正样本快。
**结论：τ 必须在开启 FR-302 查询改写的前提下标定，两者是一套。**

### 取值

PRD §11.1 的机械规则（τ_low = 负样本 p95，τ_high = 正样本 p05）在改写后给出
τ_low = 0.4126、τ_high = 0.5740。**这一对不能直接用**，两个原因：

1. 负样本只有 1 条，p95 就等于那一个点。取值恰好等于负样本分数，而分带是左闭右开
   （`max_score < τ_low` 才算无结果），于是 RAG-006 自己会落进低置信带——
   机械规则在 n=1 时会把唯一的负样本判错。
2. 同理 τ_high 恰好压在正样本最低点上，RAG-004 会掉进低置信带。

因此取**区间中点并留安全余量**：

```
τ_low  = 0.48      # 高于负样本 0.4126，低于全部正样本与低置信样本
τ_high = 0.57      # 低于正样本最低的 0.5732
```

这一对在 8 条参与标定的用例上命中 7 条：

| 用例 | 分数 | 落带 | 期望 | |
|---|---:|---|---|---|
| RAG-001 ~ 005 | 0.5732 ~ 0.7332 | normal | normal | ✅ |
| RAG-006 | 0.4126 | no_result | no_result | ✅ |
| RAG-007 | 0.5468 | low | low | ✅ |
| RAG-008 | 0.6570 | normal | low | ❌ |

### 唯一的失配：RAG-008

"金卡的积分可以怎么用？能直接抵现金吗？" 改写成"会员 金卡 积分 使用 兑换 抵现"后，
与 MEMBER-BENEFIT-001 的相似度升到 0.6570——但那条策略只说了"积分 1.5 倍"，
并不回答"怎么用"。

**这不是阈值调不对，是阈值调不了。** 试过的取值里，
任何能把 RAG-008 压进低置信带的 τ_high（> 0.6570）都会同时把 RAG-001 / RAG-004 拖下水，
净损失更大。根因是余弦相似度衡量的是**主题相关**，不是**答案包含**：
chunk 讲的就是积分，只是没讲用法。

这条留作已知缺口，两条候选解法，都不属于阈值标定：

- FR-311 cross-encoder 重排：重排模型能区分"相关"与"能回答"，是对症的；
- chunk 粒度：MEMBER-BENEFIT-001 的 rule card 把多项权益压在一起，
  拆细后"积分"那一段的分数会更诚实地反映它有多少信息。

### 落地状态与待办

- `settings.py` 仍是占位值 `rag_tau_low=0.30 / rag_tau_high=0.60`，**本次未改**——
  标定脚本只给建议，改配置需要人拍板；
- 负样本 n=1 是这次标定最大的弱点。golden 里"政策未覆盖"的主题只有海外关税一条，
  建议补到 4–5 条（如发票、换货运费、礼品卡、企业采购）后重跑，届时机械规则才真正可用；
- 复审条件不变：`low-confidence answer precision` 连续两个版本低于 90% 则回退保守方案。
