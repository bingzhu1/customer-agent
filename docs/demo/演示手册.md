## 1. 开场 90 秒（背下来）

> 我做的是一个客服 Agent，业务场景是电商售后：查订单、查物流、问政策、申请退款。
> 它和大多数"客服 AI"的区别只有一句话：**模型只负责听懂和提议，能不能退、退多少、给谁退，全部由确定性代码判定，模型碰不到。**
> 为什么这么做？因为模型输出有随机性，同一个版本跑两次评估结果都会不一样。安全类的事情不能接受随机，所以越权、注入、退款资格、金额上限这几件事，每一件都有一条不经过模型的路径兜底。
> 我先用两分钟讲架构，然后十分钟现场演示五个场景，最后用评估数字说明每加一层能力换来了什么，以及哪些还没做、为什么。

## 3. 现场演示五幕（每句都真调模型，8 到 12 秒；等"正在输入"结束再说下一句）

登录 user 101 张伟，standard 会员。右栏"本轮判定"是讲解面板，每一轮都指一下 decision 和 reason_code。

### 第一幕 · 查数据与越权（2 分钟）

| 说 | 预期 | 指给面试官看 |
|---|---|---|
| 帮我看看订单 82913 现在是什么状态？ | ANSWER / OK，工具 get_order | 右栏工具调用一行；说一句"工具参数只有 order_id，身份来自 token" |
| 帮我查一下订单 60003 的状态和收件信息。 | DENY / OWNERSHIP_MISMATCH | 这是杨静的单。回复是"没有查到这个订单" |
| 订单 77777 是什么状态？ | DENY / OWNERSHIP_MISMATCH | 不存在的单。**两句回复逐字相同**，不暴露存在性 |

讲一句：Repository 层他人与不存在都返回 None，路由统一 404，攻击者无法用订单号枚举探测。

### 第二幕 · 策略引擎与写路径（3 分钟，最重要的一幕）

| 说 / 做 | 预期 | 指给面试官看 |
|---|---|---|
| 订单 82913 我要退款。 | REQUIRE_CONFIRMATION / POLICY_SATISFIED | 确认卡：89 元、依据 REFUND-STD-001 v3、有效期。签收 16 天 ≤ 30，89 ≤ 200 |
| 点"确认退款 ¥89.00" | 回复"退款已提交" | 终端 C 跑 SQL ①，看 refunds 多一行 simulated=true，audit_log 多几行 |
| 再说一遍：订单 82913 我要退款。 | ANSWER / IDEMPOTENT_REPLAY | **不产生第二笔**。回复里的金额与时间来自 biz.refunds，不经模型 |
| 我想退订单 82915，东西没用过。 | DENY / POLICY_VIOLATION_WINDOW | 签收 35 天，超窗。拒绝话术是模板，引用条款 |
| 订单 82916 是零食，我不想要了，能退吗？没拆。 | DENY / POLICY_VIOLATION_CATEGORY | 食品条款 REFUND-FOOD-001 |
| 订单 82918 我想全额退款，东西没用过。 | REQUIRE_HUMAN / AMOUNT_ABOVE_AUTO_LIMIT | 620 > 200，转主管审批 |

SQL ①：
```sql
select id, order_id, amount, status, simulated, policy_id from biz.refunds order by id desc limit 3;
select id, action_type, status, left(idempotency_key,16) key16, expires_at from agent.agent_actions order by id desc limit 3;
select ts, actor_type, event_type, reason_code from agent.audit_log order by id desc limit 6;
```

讲两句：
- 引擎和矩阵是纯函数，无 IO 无模型，策略相关测试全部不依赖 LLM。
- 金钱的最后一道闸是数据库 UNIQUE(idempotency_key) 加执行前状态校验，不是 prompt。

**注意**：只用上面的原话。"订单 82913 的保温杯我想退款"会落进低置信带转人工，原因见 §5。

### 第三幕 · RAG（2 分钟）

| 说 | 预期 | 指给面试官看 |
|---|---|---|
| 你们的退款政策是多少天？ | ANSWER，引用 REFUND-STD-001 v3 | 右栏引用；点"查看依据的政策"跳条款锚点 |
| 海外直邮的商品关税谁承担？被海关扣了怎么办？ | REQUIRE_HUMAN / RETRIEVAL_NO_RESULT，无引用 | 相似度低于 τ_low，**不编造**，转人工 |
| 退款一般几天能到账？ | ANSWER + confidence=low，有引用 | 中间带：带确定性声明模板回答，附转人工入口 |

SQL ②：
```sql
select policy_id, count(*) chunks from agent.policy_chunks group by 1 order by 1;
```

讲一句：语料是从策略 YAML 生成的，不是人写的文档；44 个 chunk 来自 11 条规则。embedding 用 OpenAI text-embedding-3-small，存 pgvector 建 HNSW 索引，Anthropic 没有 embedding 接口。

## 5. 已知的坑，上台前记住

| 坑 | 表现 | 怎么避 |
|---|---|---|
| τ_high 在 `.env` 里是 0.50，ADR 定的是 0.57 | 同意图不同措辞可能落进低置信带，退款问句变成 REQUIRE_HUMAN / LOW_CONFIDENCE_ON_DECISION | 只用 §3 的原话 |
| `make test` 会把主库向量覆盖成假的 | RAG 分数掉到 0.05，全部转人工 | 演示前不跑 test；跑了就 §0.3 重灌 |
| 长期记忆抽取异步 | 说完立刻开新会话看不到 | 等 10 秒；SQL ④ 确认落库再继续 |
| 记忆检索是 top 5 无阈值 | 记忆条数多时，全局偏好可能被挤出 | language_preference 已固定注入；其他 key 别指望 |
| respond 不带对话历史 | 闲聊式的"刚才说的那个"接不住，只有 CaseFacts 里的订单号、工单号能接 | 第四幕短期记忆只问订单相关 |
| 余额耗尽 | 全局 DEGRADE / DEPENDENCY_UNAVAILABLE | §0.4 探活 |
| 输入框一直禁用 | StrictMode 首个会话被中断 | 点页面上的"重新连接" |
| 同一订单跨小时重复退 | 已修（`644ed63`，矩阵规则 11 读 biz.refunds），演示第二幕靠它 | 无需规避，可以主动讲 |
