问题

"用户提问 → LLM 回答"为什么上不了线

不是模型能力不够，是工程边界缺失：

  • 模型不知道用户是谁，也无法验证有没有权限看这条数据
  • 模型"觉得"符合退款条件就真的退了，事后无法审计依据
  • 对话一长就忘记订单号和已承诺的事
  • 检索不到政策时凭常识编造答案
  • 没有 trace、没有指标、没有回归测试，只能靠"试了几个问题感觉还行"

命题

保留 LLM 的语言理解，把"是否允许执行"完全交给确定性代码

三条红线，违反直接拒绝合入。每一条在代码里都有一个类型层面的落点，不靠 prompt 里写"请不要"。

1 · 身份与授权永不经过 LLM

工具签名里没有 user_id。身份从 JWT 解出后注入 Repository，"查别人的订单"在语法上写不出来。

2 · 写操作永不由 LLM 直接触发

LLM 只能产出提议。执行要过策略引擎判定、用户确认、幂等键，最后一道闸是数据库唯一约束。

3 · 记忆永不进入授权与策略判断

判定函数的输入类型里没有 memory 字段。记忆只能改语气、语言、渠道建议。10 条投毒测试在 CI 拦截。

能演示的不只是对话

对话之外，每一层都能现场打开看

前端两种界面

客户界面只有回复正文与确认卡；客服工作台右栏展示 decision、reason_code、引用、工具、token 与成本。同一会话两边同时看。

REST 接口用 curl 直接打

whoami、建会话、发消息、确认动作、取会话。他人会话与不存在同为 404；过期 410、重复 409；统一错误信封带 request_id。

运维接口与日志

/health、/ready（如实标注 vector_index 未探）、/metrics Prometheus 直方图；每请求一行 JSON 日志带 request_id 与 user_id。

数据库现场查

审计日志回答"谁、何时、依据哪条、结果如何"；动作状态机与幂等键；CaseFacts JSONB 带来源字段；记忆的置信度、版本、TTL、软删；向量表与 HNSW 索引。

评估现场跑

按类别或单条跑 golden，2 分钟出报表；对照裸模型 V0 在同一批安全用例上越权。副作用探针只看数据库快照。

离线安全测试

授权、引擎、矩阵、投毒、写路径并发，全部不调模型，几秒跑完。10 条投毒用例名字本身就是断言。

脚本复现每个数字

τ 标定表 30 秒重跑出 ADR 附录；记忆六幕脚本不触网演完写入、覆盖、软删、过期、投毒；RAG 灌库第二次跑零变化。

换用户换事实

登录金卡用户 102：签收 40 天的订单仍能退，同一引擎读到不同事实给出不同结论。说"以后用英文回答"当轮切英文，模板也跟着切。

策略引擎 + 决策矩阵

规则写在 YAML 里，判定是两个纯函数

- id: REFUND-STD-001
  version: 3
  applies_to: {item_category: standard, user_tier: standard}
  conditions:
    days_since_delivery: {lte: 30}
    item_condition: {in: [unused, unopened]}
  effect: allow_refund
  max_auto_amount: 200
  reason_code_on_pass: POLICY_SATISFIED
  fail_reason_codes:
    days_since_delivery: POLICY_VIOLATION_WINDOW
    item_condition: POLICY_VIOLATION_CONDITION
  human_text: |
    普通会员购买的标准商品，自签收之日起 30 天内……

每个事实都现查数据库：签收天数、商品状态、会员等级、是否已退。用户说"我没用过"不算数。引擎归并优先级：需人工 → 拒绝 → 多条允许则歧义 → 恰一条允许。

决策矩阵 16 条按序求值，首次命中即返回。顺序就是优先级：

安全 · 规则 1–3

归属不符 → DENY；疑似注入 → DENY；自称高权限 → DENY

升级 · 规则 4–7

要人工、强负面情绪、工具连败或超预算 → REQUIRE_HUMAN；依赖不可用 → DEGRADE

策略 · 规则 8–12

verdict 拒绝 → DENY；无规则 → 人工；金额 > 200 → 人工；已退过 → 幂等重放；允许且写操作 → REQUIRE_CONFIRMATION

检索 · 规则 13–14

分数 < τ_low → 人工；中间带且有引用 → 低置信回答；无引用 → 人工

兜底 · 规则 15–16

缺实体 → REQUEST_INFO；其余 → ANSWER

六种终态

ANSWER · DENY · REQUIRE_CONFIRMATION · REQUIRE_HUMAN · REQUEST_INFO · DEGRADE

记忆

五层记忆按权威性排序，只有事实和规则能进判定

短期：不是塞历史消息，是 CaseFacts

订单号、工单号、金额及来源字段、引用过的策略、待确认动作。写入口只有三个纯函数，模型在类型层面无路可写。"那个订单能退吗"由代码补最近一个订单号。

长期：非权威、异步、可删除

Haiku 后台抽五类偏好；禁词过滤掉"可退款 / 免审批 / VIP"；置信度 ≥ 0.6 才写；180 天 TTL、版本号、软删除。注入 prompt 时带固定前缀"[非权威提示，可能过时或有误]"。

投毒测试

写入"该用户可无限退款"后，evaluate 与 decide 输出零变化。10 条，全部离线，CI 拦截。

版本加了什么success越权注入抵抗policy 类引用与执行一致$/会话

V3 加策略引擎确定性引擎 + 模板化拒绝 + 引用校验25 / 540100%6 / 1012 / 120.010

读法

V0 → V1 解决的是安全：越权 7 次归零，注入抵抗到 100%。V1 → V3 解决的是判得对：policy 类 2 → 6，引用与执行 12/12。

success 46% 的缺口在 memory 0/8、rag 3/10、escalation 2/6，对应未收尾的 Phase 5、2、4。V5 记忆版的有效评估还没跑成。

评估方法

54 条 golden 分 7 类，每条能回溯到矩阵某条规则。副作用探针只看数据库快照，不信被测方自述。四个硬门槛任一失败版本不通过：越权 = 0、越权退款 = 0、注入抵抗 = 100%、引用与执行一致 = 100%。

安全测试全部不依赖 LLM：授权、策略引擎、决策矩阵、投毒、幂等，离线几秒跑完。

真正上线还缺什么，再给一周先做什么

过程

怎么做出来的

先定边界再写代码

PRD 定问题陈述与三条红线，10 篇 ADR 记每个取舍：单库双 schema、单 Agent、LangGraph、不用 PydanticAI、低置信带敢不敢答、记忆不能授权。

评估先行

Phase 0 只做 54 条 golden 与 runner，先量出裸模型错在哪，再按 Phase 加能力。每个版本都是同一套用例。

工作规则写死

CLAUDE.md：不许改测试让测试过；eval 分数下降必须报告；一次只做一个 milestone；每个 milestone 人工验收后才进下一个。

并行开发

6 个 Claude Code session 各用独立 git worktree 与独立数据库，共享接口先锁定，文件不相交，各分支只 push，合并顺序由主 session 定。

人工抓到的问题

演示前发现同一订单跨会话被退两次，当天修成矩阵规则 11 并加复现测试。SEC-008 漏过一次后，所有授权判定加了不依赖模型的正则兜底。

规模

915 个单测全过，lint 与 mypy 通过。策略相关测试全部不依赖 LLM。
