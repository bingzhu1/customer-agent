## B · 前端（http://localhost:5173）

| 功能 | 怎么演示 | 指什么 |
|---|---|---|
| 两种界面共用一份会话 | 登录页选"客户界面"或"客服工作台"。先在客户界面聊一句，再登录工作台打开同一会话 | 客户看到的只有回复正文、确认卡、转人工提示；工作台多出右栏"本轮判定" |
| 判定面板 | 工作台右栏 | decision、reason_code、置信、引用（policy_id + version + anchor）、工具调用及耗时、输入输出 token、美元成本、request_id |
| 确认卡 | 说"订单 82913 我要退款。" | 卡上的金额、订单、依据、有效期全部来自后端 pending_action，按钮绑真实 action_id；后端没落库就置灰 |
| 确认 / 取消 | 点"确认退款 ¥89.00"或"取消" | 确认后回复按执行回执渲染；取消后动作进终态，无副作用 |
| 依据的政策 | 回复下方"查看依据的政策" | 跳到条款锚点（如 `refund#standard`），锚点来自 chunk 元数据 |
| 语言切换 | 说"以后用英文回答"，再问任何问题；再说"请用中文" | 当轮切英文（本轮要求优先），下一轮起靠记忆；模板分支也切英文骨架 |
| 换用户 | 退出，user_id 填 102 登录 | 李娜是金卡：82930 签收 40 天仍 REQUIRE_CONFIRMATION（MEMBER-GOLD-001 延长到 45 天）。同一引擎不同事实 |
| 重新连接 | 若输入框禁用 | 页面上的"重新连接"按钮 |
| mock 模式 | `frontend/.env` 改 `VITE_USE_MOCK=1` 重启 | 不需要后端，六种 decision 各一条样本。兜底用 |

## C · REST 接口（不开前端也能演）

先取令牌（见文首）。以下每条都可直接跑：

```bash
curl -s localhost:8000/v1/whoami -H "Authorization: Bearer $TOKEN"
```
指：身份来自 token，返回 user_id 101 与 roles。

```bash
THREAD=$(curl -s -X POST localhost:8000/v1/threads -H "Authorization: Bearer $TOKEN" | python3 -c "import sys,json;print(json.load(sys.stdin)['thread_id'])") && echo $THREAD
```

```bash
curl -s -X POST localhost:8000/v1/threads/$THREAD/messages -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"message":"订单 82913 我要退款。"}' | python3 -m json.tool
```
指：响应体里 `decision`、`reason_code`、`citations`、`tools_used`、`pending_action.action_id`、`usage.estimated_cost_usd`、`latency_ms`、`request_id`。这是 PRD §8.2 的非流式响应体。

```bash
ACTION=<上一步返回的 pending_action.action_id>; curl -s -X POST localhost:8000/v1/actions/$ACTION/confirm -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"confirm":true}' | python3 -m json.tool
```
指：`status`、`reason_code`、`replay`。再打一次同一条：`replay: true`，不重复执行。

```bash
curl -s localhost:8000/v1/threads/$THREAD -H "Authorization: Bearer $TOKEN" | python3 -m json.tool
```
指：消息按时间序返回。

**404 不区分他人与不存在**（PRD §8.4）：
```bash
curl -s -o /dev/null -w "%{http_code}\n" localhost:8000/v1/threads/00000000-0000-0000-0000-000000000000 -H "Authorization: Bearer $TOKEN"
```
换 user 102 的 token 访问 101 的 thread，同样 404。

**错误信封**：不带 token 打任何 /v1 接口，返回统一的 `{error: {code, message, request_id}}`；确认过期动作返回 410，重复确认返回 409。

## D · 运维接口与日志

```bash
curl -s localhost:8000/health; echo; curl -s localhost:8000/ready | python3 -m json.tool
```
指：ready 探数据库；`vector_index: not_applicable` 是如实标注而不是假装 ok。

```bash
curl -s localhost:8000/metrics | grep -E '^(request_duration_seconds|error_total)' | head -20
```
指：Prometheus 直方图按路由与状态码分桶，错误计数按 code。

**结构化日志**：看 `make serve` 那个终端。每条请求一行 JSON，字段含 `request_id`、`user_id`、`path`、`status`、`duration_ms`；模型调用与记忆写入失败是 warning 级事件（如 `memory_search_failed`），不会冒泡成 500。

说一句：Langfuse 有配置项没接线，trace 这一项是诚实清单里的。

## E · 数据库（`make psql` 已连上）

```sql
\dn                                              -- 只有 biz 与 agent 两个 schema
\dt biz.*                                        -- 7 张业务表
\dt agent.*                                      -- 10 张平台表
```

**审计：谁、何时、依据哪条规则、结果如何**
```sql
select ts, actor_type, event_type, reason_code, left(payload::text,60) payload from agent.audit_log order by id desc limit 8;
```

**动作状态机与幂等键**
```sql
select id, action_type, status, left(idempotency_key,20) key, expires_at, executed_at from agent.agent_actions order by id desc limit 5;
```
指：proposed → confirmed → executed；同参提议命中同一 key；`UNIQUE(idempotency_key)`：
```sql
\d agent.agent_actions
```

**CaseFacts 只由代码写**
```sql
select thread_id, jsonb_pretty(case_facts) from agent.case_state order by updated_at desc limit 1;
```
指：`order_ids`、`amounts` 带 `source: order.82913.total_amount`、`relevant_policy_ids` 带版本、`last_updated_by`。

**长期记忆：置信度、来源、TTL、版本、软删**
```sql
select mem_key, mem_value, confidence, version, source_thread_id is not null as has_source, ttl_at::date, deleted_at is not null as deleted from agent.user_memory where user_id=101 order by id;
```

**向量表**
```sql
select policy_id, policy_version, count(*) chunks from agent.policy_chunks group by 1,2 order by 1;
select policy_id, anchor, left(content,40) from agent.policy_chunks where policy_id='REFUND-STD-001' order by chunk_index;
\d agent.policy_chunks                           -- vector(1536) 列与 HNSW 索引
```

**归属隔离在数据层**（对照 Repository 的 SQL）：
```sql
select id, user_id, status from biz.orders where id in (82913, 60003, 77777);
```
指：60003 存在但属于 104，77777 不存在。Agent 对两者的回复逐字相同。
